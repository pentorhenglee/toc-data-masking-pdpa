# โฟลเดอร์ tests

ที่เก็บสคริปต์ตรวจงาน คนละไฟล์ต่อคน

## กติกา 2 ข้อ

1. **ห้ามเขียนเทสให้ masker ของตัวเอง** ไฟล์ที่ได้รับผิดชอบจะเป็นของคนอื่นเสมอ
   ทำแบบนี้เพราะอาจารย์ให้คะแนนตอนนำเสนอว่างานกลุ่มเชื่อมกันไหม
   ถ้าไม่เคยอ่านโค้ดคนอื่นเลย ตอนนำเสนอจะอธิบายได้แค่ส่วนตัวเอง

2. **เขียนเทสก่อนที่ regex จะมี** อย่ารอให้คนเขียน masker ทำเสร็จ
   ให้เปิด `test_cases.md` แล้วก๊อปเคสในหมวดของตัวเองมาใส่ได้เลย
   ตอนรันครั้งแรกมันจะ FAIL หมด นั่นถูกต้องแล้ว เพราะยังไม่มีใครเขียน regex
   งานของคุณจบเมื่อสคริปต์รันได้และรายงานผลถูกต้อง ไม่ใช่เมื่อมันขึ้น PASS

## ใครรีวิวไฟล์ไหน

คนรีวิวต้องรันได้ อ่านทุกเคสเทียบกับ test_cases.md และอธิบายได้ว่าแต่ละเคสเทสอะไร
ไม่มีใครรีวิวเทสของ masker ตัวเอง

| ไฟล์ | เทส masker ของ | คนรีวิวและอธิบาย |
|------|----------------|------------------|
| test_credit_card.py | คน 2 | คน 4 |
| test_email.py | คน 5 | คน 2 (คนเขียน) |
| test_phone.py | คน 3 | คน 8 |
| test_dob.py | คน 4 | คน 9 |
| test_address.py | คน 6 | คน 3 |
| test_combined.py | ทั้ง 5 ตัวต่อกัน | คน 7 |

## วิธีรัน

รันจาก root ของโปรเจกต์ ไม่ใช่จากในโฟลเดอร์ tests

```
source venv/bin/activate
python -m tests.test_phone
```

## แหล่งข้อมูล

`test_cases.md` ที่ root คือสัญญากลาง ถ้าตรงไหนในนั้นกำกวมหรือคิดว่าผิด
ให้ถามในกลุ่ม อย่าตัดสินใจเอง เพราะคนเขียน regex ยึดไฟล์เดียวกันนี้
